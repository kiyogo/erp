# KIYO migration ledger (work in progress)

This is a working inventory, not a declaration of feature parity. `legacy/` is read-only. The supported UI remains Rust `egui`/`eframe` in `ui`, rendered to a canvas on the web and natively on desktop. API behavior belongs to the Rust Axum server.

## Sources and acceptance rule

The initial audit compared `legacy/web/src/App.tsx`, `legacy/web/src/api/endpoints.ts`, `legacy/web/src/api/axios.ts`, `legacy/api/index.mjs`, `server/src/main.rs`, and the current Rust UI views. It has **not** yet inventoried every direct HTTP call inside all legacy modules. A row is complete only after request/response shape, authorization, persistence, UI states, native/wasm builds, runtime interaction, and relevant tests are verified. Building on Windows and for the wasm target does **not** verify UI behavior in a browser or on Linux/macOS.

Current verification note (2026-10-09): the latest targeted employee-contact run passes 128 backend + 174 UI/API tests, formatter, WebAssembly target check, server build and Trunk release build. Headless Edge verified the profile contact update/reload flow and responsive dashboard/leave routes against synthetic data. This is not a workspace-wide completion check; each domain's evidence and remaining browser/native/production requirements are recorded in `docs/TEST_EVIDENCE.md`. Builds use a scratch target on C: because E: was nearly full.

## First-slice implementation notes

- The password-change response remains `{ "success": true, "message": "..." }`, matching the legacy client shape.
- Only the authenticated account can change its own password; the Rust handler obtains the user ID from the bearer token, never from a request field.
- The egui form has loading, validation, server-error and success states, and clears password fields on success. Sensitive form state is cleared on logout and when leaving the security screen; the login password is cleared after successful login.
- `SettingsView` now initializes its API endpoint from the actual session instead of a hard-coded desktop localhost value, so the web build can retain its relative `/api/v1` endpoint.
- Password changes now revoke other active server sessions in the same database transaction while retaining the current session; account deactivation revokes all active sessions. The implementation and test source remain unverified until Rust builds/tests and runtime checks can run.
- File listings are fetched from the Rust API with the session bearer token; folder creation sends the actual `context.parentId` rather than assuming a virtual root is writable. Files state is reset on logout.
- Browser CORS no longer defaults to `*`; use `KIYO_CORS_ORIGIN` only if the UI is served from a distinct development origin.
- The backend now requires explicit JWT and first-admin secrets in every build mode; it does not print a generated bootstrap password.
- Activation authorization no longer returns the raw email-link bearer as the password-setting credential. It returns an HMAC-signed activation-scope JWT tied to an unused, unexpired SQLite activation row; the normal auth middleware does not accept this JWT. Activation completion consumes it once in a transaction and returns the regular user login session. Reissuing an activation invalidates older pending links.
- The Wasm launcher detects `/activate-account`, reads only its `token` query parameter, and replaces the one-shot activation URL with `/` before mounting the canvas. Desktop provides the same activation form with manual link-token entry.
- Shared user DTO deserialization now matches Axum's camelCase wire format (`isActive`), fixing previously defaulted active-state data.
- The backend binds `127.0.0.1` by default for local development; deployment configurations explicitly select `0.0.0.0` and still require a network/TLS review.
- Admin Users uses `GET /users?page=&limit=&search=&filter=`, `POST /users`, and `PATCH /users/{id}` against real backend persistence; creating a user also creates the employee profile and protected workspace within one transaction. Search/filter run over the full directory before pagination, while total/active/admin summary values come from the full directory. The view does not claim 2FA, last-login, Excel export or print-card behavior because the current backend contract does not provide them. The legacy screen has no account edit/delete form, so none is invented in the Rust UI.
