## Rules

- Authorization is enforced server-side for each action and target resource.
- `ADMIN` may list active sessions and revoke another session; the server rejects attempts to revoke the current session through the admin route (use logout instead). `USER` cannot list/revoke sessions. Session checks run on every protected request. Password change revokes other sessions; account deactivation revokes all sessions.
- Session-event audit rows are append-only and preserve actor/subject/session identifiers after account deletion. IP address, device, location, VPN and MFA status are not exposed because the current request stack has no trusted provenance/MFA contract.
- Never trust a role, owner ID, employee ID or department supplied by the client without checking it against the authenticated principal and persisted relationships.
- Do not infer permissions from menu visibility.
- Do not broaden permissions to make a UI action work.
- Expand this matrix from actual middleware, handler checks, database ownership and tested legacy behavior.
